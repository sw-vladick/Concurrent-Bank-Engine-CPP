# Concurrent Bank Transaction Engine (C++17 / Multithreading / STL)

Високопродуктивне багатопотокове ядро для асинхронної обробки банківських транзакцій у пам'яті (In-Memory), розроблене на чистому C++17 з використанням стандартної бібліотеки шаблонів (STL).

Проєкт демонструє практичне застосування патерну Producer-Consumer, роботу з пулом робочих потоків (Thread Pool), гранулярну синхронізацію ресурсів, запобігання взаємним блокуванням (Deadlocks) та метапрограмування за допомогою Variadic Templates.

---

## Технічне завдання (Problem Statement)

Розробити потокобезпечне (thread-safe) ядро банківської системи, здатне приймати потік фінансових транзакцій і паралельно обробляти їх у фонових робочих потоках без втрати цілісності даних.

**Ключові інженерні вимоги:**
1. **Управління пам'яттю (RAII & Smart Pointers):** Зберігати рахунки клієнтів у хеш-таблиці з використанням розумних вказівників (`std::unique_ptr`), виключаючи витоки пам'яті.
2. **Асинхронна черга завдань (Producer-Consumer):** Забезпечити неблокуюче додавання транзакцій головним потоком та їх розподіл між фоновими потоками-обробниками (Workers) за допомогою умовних змінних (`std::condition_variable`).
3. **Гранулярне блокування та захист від Deadlock'ів:** Під час переказу коштів блокувати лише ті два рахунки, що беруть участь у транзакції, залишаючи решту банку доступною для інших потоків. Виключити ситуацію класичного Deadlock'у при зустрічних переказах (А -> Б та Б -> А одночасно).
4. **Потокобезпечне логування (Variadic Templates):** Реалізувати універсальний логер зі змінною кількістю аргументів довільних типів, що гарантує атомарність виводу рядків у потік `std::cout`.

## Архітектура та технічні рішення

### 1. Пул потоків та синхронізація черги (`Bank.h` / `Bank.cpp`)
* При ініціалізації `Bank` створює пул робочих потоків (`std::vector<std::thread>`), які переходять у режим очікування через `std::condition_variable::wait`.
* Це дозволяє уникнути марного навантаження процесора (Busy Waiting) — потоки сплять, доки метод `AddTransaction()` не покладе нову транзакцію в `std::queue<Transaction>` і не викличе `cv.notify_one()`.
* Коректне завершення роботи (Graceful Shutdown) реалізовано у деструкторі `~Bank()`: прапорець `std::atomic<bool> cycle` переводиться у `false`, після чого `cv.notify_all()` будить усі потоки для завершення залишку черги та виклику `.join()`.

### 2. Запобігання Deadlock'ам (`std::scoped_lock`)
* Кожен об'єкт `Account` володіє власним `std::mutex`.
* Після вилучення транзакції з черги м'ютекс черги (`mtxBank`) негайно звільняється (завдяки обмеженій області видимості `{ ... }`), і потік блокує лише рахунки відправника та отримувача:
  ```cpp
  std::scoped_lock lock(toId->second->mtx, fromId->second->mtx);
  ```
* Використання `std::scoped_lock` (C++17) застосовує алгоритм уникнення дедлоків, гарантуючи безпечне захоплення обох м'ютексів незалежно від порядку ID рахунків. Також передбачено захист від самоблокування (Self-Transfer Deadlock), коли `fromAccountId == toAccountId`.

### 3. Thread-Safe Logger на базі Fold Expressions (`Logger.h`)
* Для уникнення перемішування тексту в консолі при одночасному виводі з різних потоків реалізовано шаблонну функцію з пакетом параметрів (`template<typename T, typename... Args>`).
* Замість рекурсивного інстанціювання шаблонів використано сучасне згортання параметрів (**C++17 Fold Expressions**):
  ```cpp
  namespace Logger {
      inline std::mutex mtx;

      template<typename T, typename... Args>
      void Log(T first, Args... args) {
          std::lock_guard<std::mutex> lock(mtx);
          std::cout << first;
          (std::cout << ... << args);
          std::cout << '\n';
      }
  };
  ```
* Використання специфікатора `inline` для м'ютекса дозволяє залишати логер повністю header-only без порушення правила одного визначення (ODR).

## Структура проєкту

* `Bank.h` / `Bank.cpp` — керування життєвим циклом потоків, чергою транзакцій та пошуком рахунків.
* `Account.h` / `Account.cpp` — сутність банківського рахунку з інкапсульованою логікою депозиту та списання коштів.
* `Transaction.h` — структура даних (DTO) фінансової операції.
* `Logger.h` — потокобезпечний шаблонний логер.
* `Project(bank).cpp` — точка входу та демонстраційний сценарій паралельних переказів.

## Стек та інженерні практики

* **Стандарт мови:** C++17
* **Багатопотоковість:** std::thread, std::mutex, std::unique_lock, std::lock_guard, std::scoped_lock, std::condition_variable, std::atomic
* **Контейнери та пам'ять:** std::unordered_map, std::queue, std::vector, std::unique_ptr
* **Принципи проєктування:** RAII, Single Responsibility Principle (SOLID), Producer-Consumer Pattern, Thread Pool Pattern
